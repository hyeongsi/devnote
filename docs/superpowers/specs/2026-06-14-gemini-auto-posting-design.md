# Gemini 자동 포스팅 설계

## 목표

Google AI Studio에서 발급한 Gemini API 키를 서버 환경변수로 주입하고, DB에 등록된 개발 주제를 순환하며 매일 오전 6시(Asia/Seoul)에 게시글 하나를 자동 생성하고 즉시 게시한다.

관리자는 `/admin/ai-posting`에서 주제 목록과 실행 상태를 관리하고, 기존 수동 초안 생성, 편집, 미리보기, 저장 기능도 계속 사용할 수 있어야 한다.

## 운영 원칙

- API 키는 프론트엔드와 DB에 저장하지 않는다.
- 예약 실행 시각은 매일 오전 6시이며 기본 시간대는 `Asia/Seoul`이다.
- 활성화된 주제를 정렬 순서대로 한 개씩 선택한다.
- 마지막 주제까지 성공적으로 처리하면 첫 번째 주제로 돌아간다.
- 생성이나 게시가 실패하면 해당 주제의 순환 위치를 진행시키지 않는다.
- 같은 한국 날짜에 성공한 자동 실행이 있으면 다시 게시하지 않는다.
- 동일한 주제가 재선택되면 최근 자동 게시 제목을 Gemini에 전달해 다른 세부 주제를 선정하게 한다.

## 설정

서버는 다음 환경변수를 사용한다.

| 환경변수 | 필수 | 기본값 | 용도 |
| --- | --- | --- | --- |
| `GEMINI_API_KEY` | 운영 시 필수 | 없음 | Google AI Studio API 키 |
| `GEMINI_MODEL` | 선택 | `gemini-2.5-flash` | 생성 모델 |
| `AI_POSTING_ENABLED` | 선택 | `false` | 예약 실행 활성화 |
| `AI_POSTING_CRON` | 선택 | `0 0 6 * * *` | 예약 실행 시각 |
| `AI_POSTING_ZONE` | 선택 | `Asia/Seoul` | 예약 실행 및 일일 중복 판정 시간대 |

API 키가 없거나 자동 게시가 비활성화된 환경에서는 서버가 기동하되 예약 생성은 실행하지 않는다. 관리자 화면에는 설정되지 않은 상태를 표시한다.

## 데이터 모델

### `ai_post_topics`

- `id`: 식별자
- `name`: Gemini에 전달할 대략적인 개발 주제
- `category_id`: 게시할 기본 카테고리
- `display_order`: 순환 순서
- `enabled`: 사용 여부
- `last_succeeded_at`: 마지막 성공 시각
- `created_at`, `updated_at`: 관리 시각

주제 삭제는 실행 이력 보존을 위해 물리 삭제 대신 비활성화를 기본 동작으로 한다. 아직 실행 이력이 없는 주제만 물리 삭제할 수 있다.

### `ai_post_runs`

- `id`: 식별자
- `topic_id`: 선택된 주제
- `post_id`: 성공 시 생성된 게시글
- `status`: `RUNNING`, `SUCCEEDED`, `FAILED`, `SKIPPED`
- `generated_title`: 생성된 제목
- `error_message`: 실패 사유의 정제된 메시지
- `started_at`, `completed_at`: 실행 시각

성공 이력은 일일 중복 방지, 최근 제목 조회, 다음 주제 결정에 사용한다.

## 주제 선택

1. 활성화된 주제를 `display_order`, `id` 순으로 조회한다.
2. 성공 이력이 없는 첫 주제를 우선 선택한다.
3. 모두 성공 이력이 있으면 `last_succeeded_at`이 가장 오래된 주제를 선택한다.
4. 동률이면 `display_order`, `id` 순으로 선택한다.
5. 활성 주제가 없으면 `SKIPPED` 이력을 남기고 종료한다.

이 방식은 별도 전역 커서 없이도 순환 상태를 DB에서 복구할 수 있으며, 주제 순서 변경이나 비활성화에도 안정적으로 대응한다.

## 생성 및 게시 흐름

1. 스케줄러가 한국 시간 오전 6시에 자동 게시 서비스를 호출한다.
2. 해당 한국 날짜에 `SUCCEEDED` 이력이 있는지 확인한다.
3. 실행 대상을 선택하고 `RUNNING` 이력을 저장한다.
4. 같은 주제의 최근 성공 게시글 제목을 최대 2개만 조회한다.
5. Gemini에 주제, 카테고리 후보, 최근 제목, 간결한 분량 힌트, 출력 규격을 전달한다.
6. 구조화된 JSON 응답을 DTO로 변환하고 필수 필드와 허용값을 검증한다.
7. 제목과 주제를 기반으로 영문 slug를 만들고, 충돌 시 날짜 또는 짧은 접미사를 추가한다.
8. 기존 `PostService`의 내부 게시 생성 로직을 재사용해 게시글을 저장한다.
9. 실행 이력을 `SUCCEEDED`로 바꾸고 주제의 `last_succeeded_at`을 갱신한다.
10. 예외가 발생하면 트랜잭션을 정리하고 실행 이력을 `FAILED`로 기록한다.

동시에 여러 서버가 실행될 가능성에 대비해 대상 선택과 실행 이력 생성 구간에는 DB 잠금 또는 동등한 원자적 제어를 적용한다.

## Gemini 요청

Gemini 클라이언트는 `AiPostClient` 인터페이스를 구현하며 Mock 클라이언트와 교체 가능해야 한다.

프롬프트에는 다음을 포함한다.

- 대략적인 개발 주제
- 선택된 카테고리
- 최근 동일 주제 게시글 제목 최대 2개
- 중복 제목과 유사한 세부 주제를 피하라는 지시
- 자동 포스팅의 기본 분량 힌트 `간결하게`
- 학습형 개발 포스팅의 필수 섹션
- 사실을 확신할 수 없으면 단정하지 말라는 지시
- 코드 예제, 주의사항, 요약 요구
- 응답 JSON 스키마와 허용되는 썸네일 스타일

응답 필드는 현재 화면과 게시글 구조를 유지한다.

- `title`
- `summary`
- `content`
- `tags`
- `readTime`
- `recommendedTopics`
- `recommendedCategorySlug`
- `thumbnailStyle`

모델의 카테고리 추천이 유효하지 않으면 주제에 등록된 기본 카테고리를 사용한다.

## 관리자 API

- `GET /api/admin/ai-posting/status`: 설정 상태, 다음 실행 시각, 다음 주제
- `GET /api/admin/ai-posting/topics`: 주제 목록
- `POST /api/admin/ai-posting/topics`: 주제 추가
- `PUT /api/admin/ai-posting/topics/{id}`: 주제 수정
- `DELETE /api/admin/ai-posting/topics/{id}`: 삭제 또는 비활성화
- `PUT /api/admin/ai-posting/topics/order`: 순서 저장
- `GET /api/admin/ai-posting/runs`: 최근 실행 이력
- `POST /api/admin/ai-posting/run`: 즉시 자동 생성 및 게시
- `POST /api/ai/posts/generate`: 기존 수동 초안 생성

모든 관리 API와 생성 API는 관리자 인증을 요구한다.

## 관리자 화면

기존 수동 생성 및 결과 편집 영역을 유지하면서 다음 관리 영역을 추가한다.

- Gemini 연동 상태와 자동 게시 활성화 상태
- 다음 실행 시각과 다음 실행 주제
- 주제명, 기본 카테고리, 활성화 여부, 정렬 순서 관리
- 주제 추가, 수정, 비활성화와 순서 변경
- 최근 실행 결과, 생성 제목, 실행 시각, 실패 사유
- 확인 절차가 포함된 `지금 실행` 버튼

API 키 입력란은 제공하지 않는다. 화면에는 키의 존재 여부만 노출한다.

## 오류 처리

- 인증 실패와 API 키 누락은 관리자에게 이해 가능한 상태로 표시한다.
- Gemini 할당량 초과, 일시 오류, 응답 파싱 실패를 구분해 실행 이력에 기록한다.
- 원본 API 키, 전체 외부 응답, 민감한 서버 정보는 로그와 DB에 저장하지 않는다.
- 자동 실행 실패 시 같은 날 무제한 재시도하지 않는다.
- 관리자의 즉시 실행은 일일 성공 제한을 우회할 수 있지만, 실행 중인 작업이 있으면 거부한다.
- 게시 저장이 실패하면 성공 이력과 주제 진행 상태를 남기지 않는다.

## 테스트

### 백엔드

- 주제 선택 순환 및 비활성 주제 제외
- 같은 날짜 자동 실행 중복 방지
- 성공 시 게시글, 실행 이력, 주제 시각 갱신
- 생성 또는 게시 실패 시 `FAILED` 기록과 순환 위치 유지
- 최근 제목이 Gemini 요청에 포함되는지 검증
- 잘못된 Gemini JSON과 허용되지 않은 값 검증
- API 키 미설정 및 자동 게시 비활성 상태
- 관리자 API 인증과 CRUD 검증

### 프론트엔드

- 상태, 주제 목록, 실행 이력 조회
- 주제 CRUD, 활성화, 순서 저장
- 즉시 실행 확인 및 성공·실패 피드백
- 기존 수동 생성, 미리보기, 편집, 게시 흐름 회귀 검증

## 범위 제외

- 외부 웹 검색과 최신 뉴스 수집
- 생성 전 관리자 승인 워크플로
- 실패 작업의 자동 반복 재시도
- 이미지 생성 및 외부 이미지 업로드
- 다중 서버 전용 분산 스케줄링 제품 도입
