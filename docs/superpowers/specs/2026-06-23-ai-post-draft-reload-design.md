# AI 글 임시저장 및 재불러오기 설계

## 목표

관리자가 AI 자동 포스팅 화면에서 수동으로 생성한 글을 생성 성공 즉시 서버에 임시저장한다. 최근 자동 게시 목록에서 임시저장 기록을 선택하면 생성 결과를 다시 편집할 수 있고, 게시 완료된 기록은 다시 불러올 수 없게 한다.

## 범위

- 수동 `AI 블로그 글 생성` 요청이 성공한 경우에만 임시저장 데이터를 생성한다.
- 생성 요청 자체가 실패하거나 유효한 생성 결과를 받지 못하면 임시저장 데이터와 관련 기록을 만들지 않는다.
- 최근 자동 게시 목록에는 기존 자동 게시 실행 기록과 수동 생성 임시저장 기록을 함께 시간 역순으로 표시한다.
- 목록에는 기록의 글 제목이 아니라 생성 요청에 사용한 글 주제를 표시한다.
- 임시저장 상태인 수동 생성 기록만 클릭하여 불러올 수 있다.
- 임시저장 글을 게시하면 해당 기록을 게시 완료 상태로 전환하고 이후 불러오기를 차단한다.

## 데이터 모델

별도 `AiPostDraft` 엔티티를 추가한다. 자동 게시 실행 이력을 담당하는 `AiPostRun`에 초안 본문을 넣지 않아 두 모델의 책임을 분리한다.

`AiPostDraft`는 다음 데이터를 보관한다.

- 생성 요청의 글 주제
- 생성된 제목, 요약, 본문, 예상 읽기 시간, 썸네일 스타일, 태그
- 추천 주제와 추천 카테고리 slug
- 편집 화면에서 게시할 때 필요한 slug와 카테고리 ID
- `DRAFT`, `PUBLISHED` 상태
- 게시 완료 시 연결된 게시글 ID
- 생성 시각과 게시 완료 시각

태그와 추천 주제는 별도 컬렉션 테이블로 저장한다. 임시저장 데이터는 생성 성공 시점의 결과를 보존하며, 사용자가 화면에서 편집한 값은 게시 요청에 포함해 최종 게시글에 반영한다.

## API와 트랜잭션

수동 생성 API는 AI 응답 검증 후 `AiPostDraft`를 저장하고 `draftId`를 포함한 응답을 반환한다. 저장까지 완료되지 않으면 생성 요청 전체를 실패로 처리한다.

관리자 자동 게시 API에 다음 기능을 추가한다.

- 임시저장 상세 조회: `DRAFT` 상태인 데이터만 반환하고, 없거나 게시 완료 상태면 조회를 거부한다.
- 임시저장 게시: `draftId`와 편집된 게시글 요청을 받아 게시글 생성과 초안의 `PUBLISHED` 전환을 단일 트랜잭션으로 처리한다.

기존 일반 게시글 생성 API는 그대로 유지한다. AI 화면에서 활성 임시저장 ID가 있을 때만 임시저장 게시 API를 사용한다.

## 최근 자동 게시 목록

백엔드는 기존 `AiPostRun`과 `AiPostDraft`를 각각 최근 순으로 조회한 뒤 하나의 이력 응답으로 합치고 시간 역순으로 정렬한다. 각 항목은 표시할 글 주제, 상태, 시각, 불러오기 가능 여부, 초안 ID를 제공한다.

- 수동 임시저장: 상태 `DRAFT`, 불러오기 가능
- 수동 게시 완료: 상태 `PUBLISHED`, 불러오기 불가
- 자동 게시 성공·실패·건너뜀·실행 중: 기존 상태 유지, 불러오기 불가

프런트엔드는 `loadable` 값이 참인 항목만 버튼 형태로 렌더링한다. 클릭하면 상세 API에서 초안을 읽고 생성 결과 편집 영역, 태그, 추천 정보, 주제 및 선택 카테고리를 복원한다.

## 오류 처리

- AI 생성 실패: 기존 오류 메시지만 표시하고 임시저장 기록은 남기지 않는다.
- 임시저장 조회 시 이미 게시된 경우: 충돌 응답을 반환하고 목록을 새로고침한다.
- 게시 도중 게시글 검증이나 slug 충돌이 발생한 경우: 트랜잭션을 롤백해 초안을 `DRAFT`로 유지한다.
- 게시 성공 후에는 목록을 새로고침하고 기존 게시글 상세 화면으로 이동한다.

## 테스트

백엔드 테스트는 다음을 검증한다.

- 생성 성공 시 임시저장이 생성되고 응답에 `draftId`가 포함된다.
- 생성 실패 또는 빈 결과에는 임시저장이 생성되지 않는다.
- 임시저장 상태만 상세 조회할 수 있다.
- 게시 성공 시 게시글 생성과 `PUBLISHED` 전환이 함께 수행된다.
- 게시 실패 시 임시저장 상태가 유지된다.
- 자동 게시 기록과 임시저장 기록이 시간순으로 합쳐진다.

프런트엔드 테스트는 다음을 검증한다.

- 생성 응답의 `draftId`를 활성 임시저장으로 보관한다.
- 최근 목록은 글 주제를 표시하고 임시저장 항목만 클릭 가능하다.
- 임시저장 클릭 시 편집값과 추천 정보가 복원된다.
- 활성 임시저장은 전용 게시 API로 저장된다.

## 제외 범위

- 임시저장 내용을 편집할 때마다 서버에 자동 동기화하는 기능
- 게시 완료된 초안을 다시 임시저장으로 되돌리는 기능
- 실패한 AI 생성 요청의 별도 이력 저장
- 임시저장 삭제 및 보존 기간 관리
