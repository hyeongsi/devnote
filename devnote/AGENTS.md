# 작업 규칙

Codex는 매 작업마다 `docs/` 아래의 모든 문서를 읽지 않는다.

현재 변경과 직접 관련된 문서만 골라서 참고한다.

# 참고 문서

- Git 커밋 및 PR 규칙:
  - `docs/git-rules.md`

# PR 요청 트리거 규칙

- 사용자가 정확히 `PR 요청`이라고 말하면, Codex는 이를 "현재 작업 범위를 기준으로 커밋, 푸시, PR 생성까지 진행해 달라"는 요청으로 해석한다.
- 이 경우 Codex는 먼저 `git status`로 변경 범위를 확인하고, 관련 파일만 스테이징한 뒤 한글 커밋 메시지로 커밋한다.
- 현재 브랜치가 `main` 또는 기본 브랜치라면 `codex/` 접두사의 작업 브랜치를 만든 뒤 푸시한다.
- PR 제목과 본문은 저장소 규칙에 맞춰 UTF-8 한글로 작성한다.
- GitHub 도구 경로가 막히면 저장소의 PR 자동화 fallback 규칙에 따라 다음 가능한 방법까지 이어서 시도한다.

# 인코딩 안전 규칙

- 프로젝트의 텍스트 파일은 UTF-8 기준으로 다룬다.
- 한글이 포함된 파일을 수정할 때는 기존 인코딩과 줄바꿈 방식(CRLF/LF)을 유지한다.
- 작업에 꼭 필요하지 않다면 파일 전체를 다시 쓰지 않는다.
- 터미널 출력이 깨져 보일 경우, 그 깨진 문자열을 그대로 소스 파일에 옮기지 않는다.
- 한글 문자열과 무관한 작은 범위만 최소한으로 수정하는 패치를 우선한다.
